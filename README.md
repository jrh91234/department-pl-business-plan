# P&L Workspace

หน้าเว็บ Profit & Loss รายแผนกและ Business Plan สำหรับ GitHub Pages ใช้ Google Sheets เป็นฐานข้อมูล โดยไม่ใส่ข้อมูลการเงินจริงไว้ใน GitHub

## โครงสร้างข้อมูลล่าสุด

P&L ของเว็บเริ่มจากแผนก H9 (แท็บ `PL Input <ปี>` และข้อมูล barcode record ชุดนี้) ใช้รายการบัญชีตามรูปแบบแท็บ `BP บริษัท A` แต่ไม่ได้อ่านตัวเลขจากแท็บนั้นแล้ว เว็บอ่านเฉพาะแท็บต่อไปนี้ใน Google Sheet `Department P&L Database`:

- `Sale Price`: ราคา BP Process USD ต่อหน่วยของแต่ละรุ่น (คอลัมน์ D) คูณอัตราแลกเปลี่ยน (`O1`) จับคู่ SKU โดยตัดท้าย `-S`
- `PL Input <ปี>` (เช่น `PL Input 2026`): ต้นทุนและ BP รายเดือนที่กรอกเอง แถวละรายการตาม `BP บริษัท A` (คอลัมน์ `key` ห้ามแก้) คอลัมน์ `Jan Actual`…`Dec Actual` และ `Jan BP`…`Dec BP` ถ้ายังไม่มีแท็บ เว็บจะแสดงปุ่มให้สร้างแท็บพร้อมหัวตาราง (ผู้กดต้องมีสิทธิ์ Editor) และจะไม่เขียนทับแท็บที่มีข้อมูลแล้ว
- แผนกอื่นนอกจาก H9: แต่ละแผนกคือหนึ่งแท็บชื่อ `PL Input <ปี> <ชื่อแผนก>` (เช่น `PL Input 2026 QA`) กดปุ่ม “+ เพิ่มแผนก” บนเว็บเพื่อสร้างแท็บพร้อมหัวตาราง หรือคัดลอกแท็บ `PL Input` แล้วเปลี่ยนชื่อเองก็ได้ ชื่อแผนกบนเว็บคือ `แผนก <ชื่อ>` แผนกที่ไม่ใช่ H9 กรอกรายได้ Actual เอง เพราะ barcode record เป็นข้อมูลของ H9 หน้าภาพรวมของแผนกนั้นจึงแสดงเฉพาะโครงสร้างต้นทุน
- ชื่อรายการ: คอลัมน์ B (ชื่อหลัก) และ C (ชื่อรอง) ของแท็บ `PL Input` แก้ได้อิสระ ชื่อใหม่ขึ้นในตาราง P&L ของแผนกนั้น เว็บหาแถวจากคอลัมน์ A (`key`) เท่านั้น จึงห้ามแก้คอลัมน์ `key` และหัวคอลัมน์เดือน (`Jan Actual`, `Jan BP` …)
- รายได้ Actual ของ H9: ถ้าใส่ตัวเลขในช่องรายได้ เว็บใช้ตัวเลขนั้นแทนค่าที่คำนวณจากยอดผลิต
- `business_plans`: ประวัติ Business Plan ที่บันทึกจากเว็บ
- `Employees` (เขียนโดยระบบ Organize ใน repo `-Organize` ไม่ใช่เว็บนี้): สำเนารายชื่อพนักงานที่ซิงก์ทุกครั้งที่บันทึกพนักงาน เว็บนี้ไม่อ่านแท็บนี้ ข้อมูลพนักงานจึงไม่ปรากฏบนหน้าเว็บ แต่ทุกคนที่เปิดไฟล์ชีตได้เห็นแท็บนี้ รายละเอียดดู `docs/pl-sheet-sync.md` ใน repo `-Organize`
- barcode record · `Log` (อีกไฟล์): ยอดผลิตรายวัน

รายได้ Actual = ยอดผลิต OK จาก Log × ราคา Process USD ใน `Sale Price` รวมรายเดือน รุ่นที่หาราคาไม่ได้จะนับจำนวนแต่ไม่รวมมูลค่า และแสดงคำเตือน ยอดรวม VC, CM, FC, กำไร และกำไรสุทธิคำนวณในเว็บ ไม่อ่านจากชีต ช่องว่างนับเป็น 0 ในยอดรวม แต่ถ้าเดือนนั้นยังไม่กรอกต้นทุนเลย กำไรจะแสดง “—”

ค่าแรง (`Direct labour`, `Overtime direct` และ `- SCAN`) ให้ใส่ยอดรวมต่อเดือนใน `PL Input` เท่านั้น รายละเอียดกำลังคนเก็บในแท็บอื่น (เช่นใช้สูตรรวมยอดจากแท็บนั้น) เว็บไม่อ่านแท็บอื่นนอกจากรายการข้างบน ข้อมูลรายคนจึงไม่ถูกส่งมาที่เบราว์เซอร์ แต่ทุกคนที่มีสิทธิ์เปิดไฟล์ Google Sheet ยังเห็นแท็บนั้นได้ ถ้าต้องการปิดจริงให้แยกไปไว้อีกไฟล์

แอปโหลดข้อมูลผ่าน Google Sheets API หลังผู้ใช้อนุญาต Google OAuth และบันทึก Business Plan ไปยัง `business_plans` ผู้ใช้ที่บันทึกต้องมีสิทธิ์ Editor ในชีต หลังเลือกไฟล์ผ่าน Google Picker ครั้งแรก เว็บจำ Spreadsheet ID ใน localStorage และเก็บ access token (อายุประมาณ 1 ชั่วโมง ขอบเขต `drive.file`) ไว้ใน sessionStorage ของแท็บนั้นเท่านั้น จึงรีโหลดหน้าได้โดยไม่ต้องล็อกอินใหม่ token หายเมื่อปิดแท็บ หมดอายุ หรือ Google ปฏิเสธ (401) ไม่เก็บ refresh token เมื่อหมดเวลาให้กดปุ่มเชื่อมต่อ Google เพื่อขอ token ใหม่ด้วยสิทธิ์เดิม จึงไม่ต้องเลือกไฟล์ซ้ำ หาก Google ไม่จำบัญชีหรือสิทธิ์แล้ว ระบบจะให้เลือกบัญชีและยืนยันอีกครั้ง

## ตั้งค่า Google OAuth

1. สร้างโปรเจกต์ใน Google Cloud Console แล้วเปิดใช้ Google Sheets API, Google Drive API และ Google Picker API
2. ตั้ง OAuth consent screen เป็น External แบบ Testing และใส่บัญชี Google ที่อนุญาตเป็น Test users
3. สร้าง OAuth Client ID ชนิด Web application และเพิ่ม Authorized JavaScript origin: `https://jrh91234.github.io`
4. สร้าง API Key จำกัด HTTP referrers เป็น `https://jrh91234.github.io/*` และ `https://docs.google.com/*` และจำกัด API เป็น Google Picker API
5. วาง OAuth Client ID, API Key และ Project Number ใน `site/pl-settings.js` แล้ว commit/push
6. แชร์ Google Sheet ให้บัญชี Google ที่ใช้เข้าสู่ระบบเป็น Editor ห้ามตั้งสิทธิ์เป็น Anyone

OAuth Client ID และ API Key ที่จำกัดโดเมนเป็นค่าระบุตัวแอปซึ่งแสดงในหน้าเว็บได้ ไม่ใช่ความลับ ห้ามใส่ client secret หรือ service-account key ในรีโพนี้ OAuth scope `drive.file` ใช้ร่วมกับ Google Picker เพื่อให้ผู้ใช้เลือกและอนุญาตเฉพาะไฟล์ฐานข้อมูลที่ตั้งค่าไว้

## เผยแพร่

GitHub Actions ใน `.github/workflows/pages.yml` จะเผยแพร่เนื้อหาใน `site/` เมื่อ push ไป `main` ไปที่ GitHub Pages URL ของรีโพนี้ การเปิดหน้าเว็บไม่แสดงตัวเลขจนกว่าผู้ใช้จะเข้าสู่ระบบและได้รับสิทธิ์ในชีต

## ขอบเขตต้นแบบ

ตาราง P&L ปัจจุบันอ้างปี 2022; มกราคมเป็น Actual และเดือนถัดไปเป็น Forecast ตามหัวตาราง ข้อมูลถูกอ่านใหม่จากชีตเมื่อเข้าสู่ระบบ ส่วนแผนจะบันทึกเป็นประวัติใน Google Sheet แต่ยังไม่มีขั้นตอน Submit/Approve หรือการจำกัดสิทธิ์ตามบทบาท

ตรวจตัวอ่านและการบันทึกประวัติด้วย `node --test tests/workbook-data.test.cjs tests/sheets-bridge.test.cjs` ใช้ข้อมูลจำลอง ไม่มีข้อมูลการเงินจริงในชุดทดสอบ
